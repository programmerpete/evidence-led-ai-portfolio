Behind this step · Set the investigation scope

You choose: the demo analyst, case, UTC cutoff, relationship-search budget and whether to request model advice. The demo is currently case/account-centred, not anchored to a flagged transaction.

  • Analyst and case: GraphQL passes your demo identity to the backend, which checks case access before reading evidence. These public identities illustrate access rules, not secure bank logins.
  • Cutoff: the backend selects the latest evidence version known by that time, then checks that its event also happened by that time. A late-arriving fact is not available before the system knew it.
  • Hops: how many relationship links to explore from account A—not LangGraph steps. At the default cutoff: one hop reaches device X, two reach account B sharing it, three reach B’s AUD 2,400 transfer to C. Access, freshness and cutoff rules still apply.
  • Start new run: sends the settings to the GraphQL startRun mutation. The backend collects evidence, LangGraph drafts cited facts, optionally requests model advice, then pauses for human review.

Check before starting: the cutoff is UTC, the search is bounded, and external model advice is optional and may cost money. Changing settings does not refresh a saved run; starting again creates a separate snapshot.

    Behind this step · Freeze and pause

    The run ID links a frozen evidence snapshot, any requested model assessment and audit history. LangGraph saves a database checkpoint at its human_review interrupt. “Awaiting review” means execution is paused—not that an AI is still working in the background.

    Limitations & coverage

      Cited facts

      Behind this step · Draft the facts

      LangGraph’s deterministic draft_cited_facts node copies descriptions from available evidence and attaches their evidence IDs. An LLM does not write these facts. Other source states become limitations instead of supporting findings.

      Follow a citation to its evidence card. A shared device is a lead, not proof that accounts belong to the same person or that a payment is fraudulent. “No findings” can mean insufficient visible evidence—not that the activity is safe.

        Evidence register

        Source states are shown as returned. Denied evidence stays redacted; an unavailable source is not a negative finding.

        Behind this step · Check sources and gaps
        • Available: permitted evidence eligible at this cutoff; it can support a fact.
        • Stale: more than seven days old at the cutoff under this demo policy. It is not used as current support and does not expand the search.
        • Denied: source content is redacted because access is restricted.
        • Unknown: no graph evidence is visible for this search and cutoff.
        • Unavailable: an integration cannot supply evidence; the watchlist integration is not configured in this lab.

        Check: event time is when an observation happened; known-at time is when it entered the system. Version, source and batch identify the selected record’s lineage, not independently verified truth. Missing data is neither proof of fraud nor proof of innocence.

        Model recommendation

        AI suggestion — analyst decides. Citations are checked; reasoning is not verified. Not a fraud probability.

        Behind this step · Request optional AI advice

        If you opted in when starting this run, LangGraph’s model_advice node sends available permitted evidence content, source IDs/states, cutoff and limitations to the configured OpenAI or OpenRouter endpoint. Non-available source descriptions and metadata are excluded. It requests a recommendation, short rationale, citations and gaps—not a fraud probability.

        The backend validates the response structure and checks that citations refer only to available evidence. These checks do not prove the rationale is correct. Missing configuration, insufficient supporting evidence or failed provider/response checks leave advice unavailable; human review still works.

        Check: compare the suggestion with its cited sources and gaps, and make your own decision. Advice is saved with this run. Opening this explainer or reloading the run does not call the model again.

        Human review

        Decision applies only to the displayed run

        Behind this step · Save the human decision

        You choose escalate, close or request information and explain why. The GraphQL reviewRun mutation saves your identity, decision and rationale with an audit event before resuming LangGraph’s checkpoint. The model cannot submit this review.

        Resume pending: the decision is saved, but graph completion has not been confirmed. Retry exactly the saved review; do not replace it. Reviewed: the graph has finished with that review and the record is locked. A competing different review is rejected.

        “Close” records an analyst decision for this snapshot; it does not close a bank account or the case lifecycle. No choice blocks a payment or files a report. The original draft still says human review is required; the separate run status records whether that review has completed.

        Review target:

        10–2,000 characters. Explain the decision and any evidence gaps.

        How this demo works

        A deterministic graph gathers synthetic evidence and drafts cited facts without an LLM. If requested for a new run, optional model advice is generated before the graph pauses on a persisted checkpoint for human review. Model advice never sets the human decision or rationale. A saved decision resumes that graph; if resume is pending, retry only the saved decision. “Reviewed” means this run’s review completed—it does not block an account or close the case lifecycle. Demo analyst tokens are public impersonation identities, not production authentication. Missing, stale, denied, or unavailable evidence limits what can be concluded.
